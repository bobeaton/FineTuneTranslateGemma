# Fine-tuning TranslateGemma for Hindi ↔ Kangri

This workspace fine-tunes Google's **[TranslateGemma 4B](https://huggingface.co/google/translategemma-4b-it)**
(`google/translategemma-4b-it`, released 2026-01-12, built on Gemma 3) on a
Hindi (`hi`) ↔ Kangri (`xnr`) parallel corpus drawn from the Kangri New
Testament translation plus additional Bible-study couplets.

> **Why the 4B model?** This machine has an NVIDIA RTX 4060 Laptop GPU with
> 8 GB VRAM. With 4-bit quantization (QLoRA) the 4B model trains comfortably
> in that budget; the 12B and 27B variants do not fit for training.

## Layout

```
data/                          merged training dataset (JSONL)
scripts/
  merge_csv_into_dataset.py    merges CSV couplets into the JSONL dataset + dedup
  finetune_translategemma.py   QLoRA fine-tuning (TRL SFTTrainer)
  merge_adapter.py             folds the LoRA adapter into the base weights -> models/
  translate.py                 run translations with the base or fine-tuned model
  check_env.py                 verify packages, GPU, and gated-model access
  tg_common.py                 shared prompt rendering / model resolution
docker/                        translation webservice container (see docker/README.md)
models/                        merged model for serving (gitignored, 8+ GB)
output/                        training checkpoints and the final LoRA adapter (gitignored)
requirements.txt               Python dependencies (see setup below for torch)
Handoff.md                     what was done in each session + current status
```

## Dataset

`data/GemmaDataSet_HIN_XNR_Total.json` — **58,052 examples**, JSONL, one
training example per line in TranslateGemma's own fine-tuning format:

```json
{"messages":[
  {"role":"user","content":[{"type":"text","source_lang_code":"hi","target_lang_code":"xnr","text":"<Hindi>"}]},
  {"role":"assistant","content":[{"type":"text","text":"<Kangri>"}]}]}
```

Every sentence pair appears in **both directions** (hi→xnr and xnr→hi), so one
fine-tune serves both translation directions.

Provenance:

| Source | Examples |
|---|---|
| `GemmaDataSet_HIN_XNR_NT.json` (NT, generated by the C# `TranslateGemma.cs` class) | 45,230 |
| `Addl Hindi-Kangri Couplets (spellfix).csv` (7,505 pairs × 2 directions) | 15,010 |
| duplicates removed (same direction + same source & target text) | −2,188 |
| **Total** | **58,052** |

## Setup

Python **3.12** (3.14 is too new for the ML stack). One-time setup:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

TranslateGemma is a **gated model**: you must accept the Gemma license at
<https://huggingface.co/google/translategemma-4b-it> while signed in, and have a
Hugging Face token available (`huggingface-cli login`, or the `HF_TOKEN`
environment variable — this machine already has one cached).

Until the license is accepted, the scripts automatically fall back to
`Infomaniak-AI/vllm-translategemma-4b-it`, an ungated full-precision re-upload
of the same weights (already downloaded to the local HF cache). The prompt
rendering is identical either way — `scripts/tg_common.py` adapts to whichever
chat-template style the loaded model ships with.

Verify everything:

```powershell
.venv\Scripts\python.exe scripts\check_env.py
```

## Fine-tuning

```powershell
# quick smoke test (a few minutes once the model is downloaded)
.venv\Scripts\python.exe scripts\finetune_translategemma.py --limit 200 --max-steps 10 --output-dir output/smoke

# full run (1 epoch over ~58k examples; many hours on this GPU)
.venv\Scripts\python.exe scripts\finetune_translategemma.py

# resume an interrupted run from the last checkpoint
.venv\Scripts\python.exe scripts\finetune_translategemma.py --resume
```

What the script does:

- loads the base model in **4-bit NF4** (bitsandbytes) with bf16 compute
- attaches **LoRA** adapters (r=16, α=32) to the attention + MLP projections of
  the *language model only* (TranslateGemma keeps Gemma 3's vision tower; it is
  left untouched)
- renders every example with the model's **own chat template** (which
  understands `source_lang_code`/`target_lang_code`), pre-tokenizes, and drops
  the few examples longer than `--max-length` (512) tokens rather than
  truncating them
- trains with batch 1 × gradient-accumulation 16 (effective batch 16),
  gradient checkpointing, paged 8-bit AdamW, cosine LR schedule from 1e-4
- holds out 200 examples for eval; evaluates and checkpoints every 250 steps
  (`save_total_limit=2`), so an interrupted run loses at most 250 steps
- saves the final LoRA adapter to `output/translategemma-4b-hi-xnr-lora/final`

Useful knobs: `--epochs`, `--max-steps`, `--limit`, `--lr`, `--lora-r`,
`--batch-size`, `--grad-accum`, `--max-length`.

## Using the fine-tuned model

```powershell
# Hindi -> Kangri
.venv\Scripts\python.exe scripts\translate.py --direction hi2xnr --text "यीशु ने कहा, मैं ही मार्ग हूँ।"

# Kangri -> Hindi
.venv\Scripts\python.exe scripts\translate.py --direction xnr2hi --text "..."

# compare with the stock model (no adapter)
.venv\Scripts\python.exe scripts\translate.py --direction hi2xnr --text "..." --base-only

# interactive mode: omit --text and type lines
.venv\Scripts\python.exe scripts\translate.py --direction hi2xnr
```

The adapter is small (~57 MB) and loads on top of the 4-bit base model, so
inference also fits in 8 GB VRAM.

## Serving as a webservice (Docker)

The [docker/](docker/) folder hosts the fine-tuned model behind a localhost
endpoint compatible with the NLLB Translator EncConverter (SILConverters),
supporting **all** of TranslateGemma's languages plus Kangri, in **both**
directions (including the `directionForward` flag):

```powershell
# one-time: fold the adapter into the base weights
.venv\Scripts\python.exe scripts\merge_adapter.py

# build + run (GPU, background)
cd docker
.\buildDocker.ps1 -Gpu -Detached
```

See [docker/README.md](docker/README.md) for the API and all options.

## Notes & caveats

- **Kangri support**: `xnr` is not in TranslateGemma's officially supported
  language list — that is exactly why we fine-tune. The model's Gemma
  tokenizer handles Devanagari well, so only the adapter weights need to learn
  the language.
- The GPU is a 60 W laptop part; measured speed is ~20 s per optimizer step
  (batch 16), i.e. roughly 20 hours for a full epoch.
  Training checkpoints every 250 steps, so interruptions are cheap (`--resume`).
- Keep the laptop plugged in and prevent sleep during training
  (Settings → System → Power, or `powercfg /change standby-timeout-ac 0`).
